# Ayasofya Implementation Plan

> **For agentic workers:** Execute tasks against the approved design. Root owns
> model generation and verification; render worker owns LDraw fetching/rendering.

**Goal:** Deliver a real-part Ayasofya LDR, shopping list, preview and build steps.

**Architecture:** A constrained stud-grid model is packed with a small catalogue
of real bricks and plates. An independent occupancy/contact validator checks the
assembled model, then exporters write LDraw, BOM and step data. Rendering uses
official part geometry, never a concept image.

**Tech Stack:** Python 3 standard library, LDraw, Blender 5.2.1.

**Spec:** `docs/superpowers/specs/2026-09-06-ayasofya-design.md`

## Global Constraints

- Taban: 48 × 48 stud, 38,4 × 38,4 cm; hedef 1.500–2.500 parça.
- Standard stud connections only; no custom parts, glue or deformation.
- Physical strength is untested and must be distinguished from digital checks.
- No Git operations: the provided directory is not a Git repository.

## Execution

- [x] Task 1 — `tests/test_model.py`, `scripts/model_core.py`: test collision,
  unsupported bricks, disconnected plinths and rotated LDraw placement using
  hand-derived small fixtures; implement geometry and contact validator.
  Run `python3 -m unittest discover -s tests -v` before and after implementation.
- [x] Task 2 — `scripts/build_model.py`: create 48-stud interlocked base, lower
  shell, internal supports, raised central body, supported stepped domes and
  four minarets. Reuse the verified part placement interface. Generate flat
  `dist/ayasofya.ldr`, JSON placement data and per-layer STEP sequence.
- [x] Task 3 — `scripts/export_model.py`: derive CSV and BrickLink XML from the
  final placements; test their totals and part/color identities against parsed
  LDR output. Verify every used pair against catalog evidence.
- [x] Task 4 — `scripts/fetch_parts.py`, `scripts/render_model.py` (worker): fetch
  official LDraw definitions, preserve license metadata, recursively transform
  their geometry and render the final model with Blender. Inspect both views.
- [x] Task 5 — `README.md`, `dist/yapim-rehberi.html`, `dist/dogrulama.json`:
  present measured dimensions, counts, limitations and reproducible commands.
  Include step-specific part lists and plan views; verify delivered artifacts.

Tasks 1–3 are sequential because they share the placement representation.
Task 4 can proceed alongside them until it needs the generated LDR. Final
verification includes all generated outputs and catalogue checks. Corrections
to the model require regeneration of BOM, steps and previews together.
